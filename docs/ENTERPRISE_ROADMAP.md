> **Docker environment trap (2026-08-18):** the `et-*` containers can silently be
> bind-mounted to a stale, unrelated checkout (found pointing at
> `...\downloads\compressed\et\api` instead of this repo) if a same-named
> (`et`) compose project was ever started from another directory on this
> machine — Docker Compose's default project name is just the folder's
> basename, so two different checkouts both named `et` collide. Symptom: Pest
> runs "pass" but show none of the test names you just wrote. **Before trusting
> any container-based test/lint run**, verify with
> `docker inspect et-api-1 --format '{{range .Mounts}}{{.Source}}{{end}}'` —
> it must print this repo's `api` path. If it doesn't, `cd` into this repo and
> run `docker compose up -d` to recreate the containers against the right
> mount (safe, idempotent). Separately, `phpunit.xml`'s `DB_CONNECTION=sqlite`
> `<env>` does not override the container's real `DB_CONNECTION=mariadb` OS
> env var (no `force="true"`) — force it per-invocation with
> `docker exec -e DB_CONNECTION=sqlite -e DB_DATABASE=:memory: ...` or tests
> collide against the shared dev database.
