# ── 1. Scheduler ────────────────────────────────────────────────────────────
# Laravel's own dispatcher. Must run every minute; it decides internally what
# is actually due.
* * * * *  cd ~/ethr/api && php artisan schedule:run >> /dev/null 2>&1

# ── 2. Queue worker ─────────────────────────────────────────────────────────
# --stop-when-empty, NOT a daemon: shared hosting runs no supervisor, so the
# process must exit rather than linger. --max-time=50 keeps it inside the
# one-minute window so runs never overlap.
#
# The --queue list is the authoritative one, QueueHealth::QUEUES. Order is
# meaningful (Laravel drains left to right, so `attendance` leads); membership
# is the correctness property — a queue missing here is a queue nothing drains.
* * * * *  cd ~/ethr/api && php artisan queue:work --queue=attendance,notifications,default,exports --stop-when-empty --max-time=50 --tries=3 --backoff=10 >> /dev/null 2>&1

# ── If only "Fetch a URL" tasks are offered ─────────────────────────────────
# Then neither line above can run, and the scheduler and queue move behind an
# authenticated HTTP endpoint instead.
#
# THAT ENDPOINT NOW EXISTS. Built and merged 2026-09-22 (b61cb05); this section
# said "UNBUILT ... must be costed, not assumed" until then. Two tasks, same
# one-minute interval, same split and for the same reason as above:
#
#   POST https://ethr.et/api/v1/cron/schedule
#   POST https://ethr.et/api/v1/cron/queue
#
# AUTHENTICATION. Set CRON_TOKEN in api/.env to at least 32 random characters:
#
#   php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
#
# Present it as the X-Cron-Token header where the caller sets headers. Plesk's
# fetch-a-URL task cannot, so ?token=... on the query string is accepted too:
#
#   POST https://ethr.et/api/v1/cron/schedule?token=YOUR_TOKEN
#
# The query form puts the token in access logs and Referer headers. Prefer the
# header wherever the caller allows one; treat a query-form token as rotatable.
#
# WHAT TO EXPECT, so a silent failure is not mistaken for success:
#
#   200  ran. JSON body carries exit_code and tailed output
#   409  the previous run is still going. Normal under load, not an error
#   404  CRON_TOKEN unset, shorter than 32 chars, or the token did not match.
#        404 rather than 401/403 is deliberate: an unconfigured deployment must
#        not confirm these routes exist. So a 404 here means CHECK YOUR TOKEN --
#        it does not mean the route is missing
#   429  more than 10 requests in a minute from one IP
#
# POST, not GET. A GET would be followed by a crawler or link prefetcher.
#
# THIS DOES NOT MAKE G0-D PASS. G0-D asks whether the HOST can run a command; it
# still cannot, and on this subscription there is no Scheduled Tasks section at
# all -- not even a fetch-a-URL task to point at these. See GATE-0-RESULT.md ->
# G0-D. What changed is that the driver no longer has to be the host: an uptime
# monitor, a GitHub Actions cron, or any always-on machine will do.
