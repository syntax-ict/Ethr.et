# E2E specification 08: communication, insight, integrations, platform console and marketing site

Columns, personas and modes: see the [README](README.md#how-a-test-case-is-written). Tenant cases run in
QA Audit; console cases on `https://admin.ethr.et` as PA against QA or `uat-` organisations only.
Notifications and emails are queued and production has no worker: the queue is drained every 5
minutes, so allow 10 before recording a notice as missing.

**Third edition (2026-11-08).** Cases were added for Get help (#471, and the owner's phone from the
A-Z review train #624), reports and analytics (#472, #474, #477, #479), dashboards (#467, #561, #569,
#571, #574, #575, #578, #581, #584, #591, #594, #597, #633), charts and printing (#613, #614, #615,
#617, #619), the console's feature controls (#464, #480, #636), tenant journey (#643), an
organisation's administrators and owner (#625), backups, disk and mail (#509, #517, #530, #532,
#534), the release schema check (#620), public pages and notices (#466, #482, #507, #510, #519,
#632) and webhooks (#489, and the delivery id and held deliveries from #624). Existing cases these
changed were corrected in place. Since then (2026-11-09) EXP-001 covers exports the host stopped
(#669) and kiosk token hashes left out of the archive (#679). The tenant side of the feature controls is file 03's (PLAN-014 to
PLAN-021, AUTH-039, ORG-008); section 9b covers only the console screens.
Priorities were re-tiered: **P1** is kept for cross-organisation or cross-department exposure (in
dashboards, search, help requests and console reads), API key scope, webhook signatures, secrets
kept out of responses, backups not taken, figures someone acts on (payroll, attendance and revenue
totals), and the one happy path of each section. Main flows, messages and lesser refusals are
**P2**. Chart look, print layout and request counts are **P3**.
