## UX audit: 285 passed, 18 failed, 2 flaky

The last clean figure was 288 passed, 0 failed (run 39831687749, 2026-10-22, `main@2c3cdfb2`). Each failure below repeats in each theme it fails in, which is why 6 defects make 18 failures.

**Real defects, 12 failures on 3 screens:**

| Screen | Themes | Rule | What is wrong | Slice |
|---|---|---|---|---|
| `/shifts/roster` | light, dark, high contrast | axe `color-contrast` (serious) | The "Regular" chip on a non-working day is drawn at `opacity-40`, which gives **2.02:1** where 4.5:1 is required (`#a3b1de` on `#f7fafe`, 12px) | S2 (one-line fix; the chip should say the day is off, not fade the text) |
| `/settings/leave-types` | light, dark, high contrast | axe `label-content-name-mismatch` (serious, WCAG 2.5.3) | The weekday toggles show "Mon" but are named `aria-label="Monday"`. The visible text must be part of the name | S3 (the settings hub; those toggles move to the segmented control) |
| `/admin` and `/admin/audit` | light, dark, high contrast | console clean | `GET /api/v1/admin/audit` answers **403** for the seeded super admin (`Gate::authorize('admin.manage')`). The other console pages answer, so this is one endpoint, not the sign-in | **Diagnose first.** Frontend only: if the account may not read it, the console must not ask. If it may, this is a backend or seed defect, reported to the owner and left alone under this plan |

**Caused by the audit run itself, 6 failures and 2 flaky:**
- **HTTP 429.** The audit signs in as one user and opens pages faster than the 300-per-minute limit allows, which affects `navigation/badges`, `auth/me`, `lookups` and others. This was seen and decided on 2026-10-22: the dashboard is exempt by design, and the audit's exemption is not widened.
- **`net::ERR_ABORTED` on `_next/static/chunks/*`.** The dev server was still sending a page's JavaScript chunks (recharts, zod and app chunks) when the audit moved to the next page.
- **Where:** the dashboard shell (dark, high contrast), the dashboard (dark, high contrast; light was flaky), Add employee (dark; high contrast was flaky), API keys (light).

**What this changes in the plan:**
- **The target needs restating.** "At least 288 / 0" is the bar, and today is below it. Per screen the target becomes **0 real failures**.
- **The audit should stop failing itself** (S14 tooling):
  - a short pause or retry on 429 that still counts the page;
  - aborted chunk loads ignored only when the page finished navigating.

  Without these, every run shows the same 6 or so and people stop reading it.
